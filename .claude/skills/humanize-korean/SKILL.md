# humanize-korean — AI 티 없는 한국어 (우리 프로젝트판)

원본 = epoko77-ai/im-not-ai v2.3.2 (MIT, `LICENSE`) — 사용자 2026-11-10 「https://github.com/epoko77-ai/im-not-ai 이 스킬도 있으니 AI티도 안나게 적용해주고」. 원본 오케스트레이터 전문 = `SKILL.upstream.md` (참고용). **원본 스크립트 (shim · verify_gates · metrics · install.sh) 는 들여오지 않았고 실행하지 않는다** — 규칙 문서만 씀 (받은 저장소 = `D:\godot_data\ext\im-not-ai`, 신뢰 안 함).

## 규칙 출처 (먼저 읽을 것)
- `references/quick-rules.md` — 패턴 ID (A 번역투 · B 영어 과다 · C 구조 · D AI 관용구 · E 리듬 · F 수식 · …) 정의 1줄 + 처방 1줄. **대부분은 이것만으로 충분.**
- 애매하면 `references/diagnosis-rules.md` (빠른 판정) → `references/rewriting-playbook.md` (고치는 법) → `references/ai-tell-taxonomy.md` (전체 85패턴 · 예문 — 큼, 해당 ID 만 grep).

## 네 가지 철칙 (원본)
1. **의미 불변** — 내용 · 수치 · 고유명사 · 효과는 한 글자도 안 바뀜. 핵심 명사 (내용 앵커) 는 결과에 그대로 남김.
2. **근거 기반** — 패턴 ID 로 짚을 수 있는 곳만 고침. 취향 윤문 금지.
3. **장르 유지** — 게임 UI 글은 짧고 단정한 게임 말투 그대로 (설명문 · 에세이로 바꾸지 않음).
4. **과윤문 금지** — 바꾼 글자 비율 30% 넘으면 다시 보고, 50% 넘으면 되돌림 (짧은 UI 글은 한 줄 단위로 판단).

## 게임 글 (strings.csv) 에 쓸 때 — 우리 규칙
- 대상 = `resources/i18n/strings.csv` 의 **ko 열만** (en · ja · zh 는 안 건드림). 같은 글이 `resources/data/*.csv` desc 열에도 있으면 둘을 같게 (qa_check 가 대조하면 그 규칙대로).
- **손대면 안 되는 것**: 자리표 `{v}` `{n}` `%s` `%d` · BBCode `[color=…]` `[b]` · 숫자 · 단위 · % · 초 · 칸 · 게임 용어 (직업 · 종족 · 시너지 · 특성 · 유물 이름 — 이름 열 `*.name` 은 원칙적으로 그대로) · 키 이름 · 줄바꿈 `\n` 위치 (화면 줄 수).
- **i18n 폭**: 줄 수 · 글 폭 한도 (i18n 시험 — `tools/godot/tests` 의 i18n 단계) 를 넘지 않게 — 짧아지는 쪽은 괜찮고 길어지면 안 됨.
- 게임 글에서 자주 보이는 AI 티 (우선 고칠 것): A-3 「~에 있어」 · A-5 「~와 관련하여」 · A-6 「~을 바탕으로」 남발 · A-7 「~을 가지고 있다」 · A-8 이중 피동 · A-9 「~에 의해」 · A-19 「~에서의 / ~으로의」 · D-2 의의 과장 · D-3 「다음과 같은」 도입 · F-4 · F-5 「~적 N」 명사화 체인 · F-7 범용 정책 동사 (강화 · 확보 · 구축 · 제공) · C-11 연결어미 뒤 쉼표 · E-2 같은 어미 연속 (툴팁 여러 줄이 전부 「~합니다」 등).
- 게임 효과 글은 「무엇이 · 얼마나 · 언제」 가 바로 읽히게: 「적에게 공격력의 120% 피해를 줍니다」 처럼 주어 생략 · 동사 직결 · 명사 나열 대신 동사.
- 말투 = 그 키 묶음의 기존 말투 (해요체 / 합쇼체 / 명사형 「~함」 · 「~ 피해」) 를 섞지 않음 (E-7).
