게임을 만들다 보면 코드보다 **결정**이 더 빨리 잊힙니다. 왜 이 구조를 골랐는지, 어떤 함정을 밟고 돌아 나왔는지는 커밋 메시지에 다 담기지 않습니다. 이 데브로그는 그 빈자리를 채우려고 만들었습니다.

## 여기서 다룰 것

| 주제 | 예시 |
| --- | --- |
| Unreal Engine 내부 동작 | GAS, 게임플레이 프레임워크, 복제 |
| 트러블슈팅 | 크래시 추적, 댕글링 포인터, 타이밍 버그 |
| 설계 결정 | 선택지 비교와 그 선택이 갈린 이유 |
| 회고 | 프로젝트를 마치고 다음에 다르게 할 것 |

## 기록 원칙

1. **무엇보다 왜** — 구현 자체는 코드가 말해 줍니다. 글은 판단의 근거를 남깁니다.
2. **함정은 크게** — 다시 밟지 않도록, 헷갈렸던 지점은 따로 표시합니다.
3. **짧게** — 핵심은 표로, 흐름은 그림으로, 문장은 필요한 만큼만.

> [!TIP]
> 오른쪽 위 검색 버튼이나 키보드 <kbd>/</kbd> 로 글을 바로 찾을 수 있습니다.

앞으로 잘 부탁드립니다.
